JOURNEY · 04

Why wasn't the original .NET enough?

I had just started understanding .NET as a common platform. Then another question appeared: why did Microsoft need .NET Core?

01

THE QUESTION

If .NET already existed, why create .NET Core ?

So I initially thought:

If .NET already solves the platform problem, what problem was left for .NET Core to solve?
02

THE OLD WORLD

The original .NET was built around Windows.

The .NET Framework had grown closely around the Windows ecosystem.

It worked well for building applications in that environment, but software development was changing.

03

THE WORLD CHANGED

Applications were no longer living in one environment.

Developers increasoingly needed applications to work across different operating systems and deployment environments.

Windows
Linux
macOS
↓ Cross-platform applications
04

THE PROBLEM

The existing foundation wasn't designed for this new world.

Microsoft could continue adding features to the existing .NET Framework.

But the bigger question was whether the existing foundation was the right foundation for a cross-platform future.

Maybe the solution wasn't to keep extending the old foundation.
05

THE NEW DIRECTION

Microsoft built a new foundation.

Instead of simply extending the existing .NET Framework, Microsoft created a new implementation of .NET designed around cross-platform development.

.NET Framework
↓
New .NET foundation
06

.NET CORE

This new direction became .NET Core.

.NET Core was designed to be cross-platform, open source and modular.

This meant developers could use .NET beyond the Windows-only world of the traditional .NET Framework.

Cross-platform

Applications could target Windows, Linux and macOS.

Open source

The platform was developed openly with the community.

07

WHAT CHANGED FOR ME

C# didn't suddenly become a different language.

This was an important distinction for me.

C# remained the language I was writing. The change was in the platform and runtime underneath it.
