01

THE QUESTION

Why is all this code in Program.cs?

I knew C# fundamentals such as variables, methods, classes and objects.

But when I started working with an ASP.NET Core application, I opened a file called Program.cs and saw code that I couldn't fully explain. 

                            
                                var builder = WebApplication.CreateBuilder(args);
                                var app = builder.Build();
                                app.Run();

The syntax was familiar. The purpose of the code was not.

What exactly is happening inside Program.cs?
02

THE FIRST REALIZATION

Program.cs is still just C#.

One of the first things I had to understand was that Program.cs wasn't a new language or a special type of syntax.

It is a C# source file.

Instead of mainly containing business logic such as calculating an order total or retrieving a customer, this file is primarily used to configure the application and define how it starts.

C# code Program.cs
↓
Configure application
↓
Start application
03

THE BUILDER

So what is the builder?

The first line that caught my attention was: 

                            
                                var builder = WebApplication.CreateBuilder(args);

At first, I saw this as just another variable being created.

But the important part was what CreateBuilder() was preparing for.

It creates a builder that gives the application a place to configure the services, configuration, logging and other parts needed before the web application is built.

CreateBuilder()
↓
Application configuration
04

SERVICES

Where do the application's services come from?

While exploring Program.cs, I started seeing code like: 

                            
                                builder.Services.AddControllers();

This introduced another concept: services.

An ASP.NET Core application can depend on many objects and services. Instead of manually creating every object throughout the application, services can be registered with the dependency injection container.

Program.cs
↓
Register services
↓
DI container

I didn't understand dependency injection fully at this point, but I now had a place to continue my investigation.

05

BUILD

Then what does Build() actually do?

After configuring the application, I found another line: 

                            
                                var app = builder.Build();

This was another important distinction.

The builder is used to prepare and configure the application. Calling Build() creates the web application from that configuration.

Builder
↓
Build()
↓
WebApplication
06

THE REQUEST PIPELINE

But building the application wasn't the whole story.

I then started seeing code such as: 

                            
                                app.UseHttpRedirection();

                                app.UseAuthentication();
                                app.UseAuthorization();
                                
                                app.MapControllers();

                                app.Run();

These lines configure how the application handles incoming HTTP requests. Middleware can inspect or modify a requst as it moves through the pipeline, while endpoint mapping determines which application code can handle the request.

HTTP Request
↓ Middleware ↓ Routing ↓ Endpoint ↓
HTTP Response
07

THE BIGGER PICTURE

Program.cs started making more sense.

I was beginning to see that Program.cs wasn't simply a file where someone had put a collection of unrelated C# statements.

It was participating in the setup of the application.

CreateBuilder() Prepare
↓
Configure Services & application
↓
Build() Create application
↓
Configure pipeline Process requests
